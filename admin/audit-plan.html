2.2 · Independent AI code review

A reviewer agent re-reads the shipping surface (admin/index.html, Edge Functions, migrations 006-094) cold every release. Reports findings as P0 (stop-the-line) / P1 / P2 with file:line citations. 2.3 · Continuous functional self-test

app.skateos.com/selftest.html runs 33 probes on demand, including 5 end-to-end workflow chains:

  • POS sale insert → receipt_number trigger fires → row written

  • Refund: status → refunded → loyalty_reverse trigger

Re-runnable by anyone with browser access. Failures surface in red with the exact RPC + payload.

4.2 · Public-facing webhooks must include --no-verify-jwt

Stripe/Brivo/Frigate/Smartwaiver/Helcim webhooks are HMAC-signed at the function layer, not JWT-gated. Forgetting --no-verify-jwt on these deploys causes Supabase to reject every webhook before the function ever runs. Codified in admin/deploy-functions.sh.

5 · Staged rollout / sign-off plan

Each phase is independently reviewable. Kenan can stop the chain at any phase by withholding sign-off.

Phase A · Read-only (already in production)

  • Square catalog/customers/orders ingest, daily refresh crons green
  • Reports queries (real numbers, see §1)
  • Customer portal magic-link auth, lessons booking RPC

Live since 2026-04 · No customer impact

Phase B · Mirror mode (active now, parallel to Square)

  • Cash sales rung in skateOS POS alongside Square (dual entry for one week to verify totals match)
  • Walk-up Check-ins via skateOS Front Desk only; Square handles cards
  • Stripe Tap-to-Pay in TEST mode for staff dry-runs

Acceptance gate: Daily reconciliation page (admin/cutover.html) shows |skateOS gross − Square gross| < $5 for 5 consecutive business days.

Phase C · Cards live (Stripe LIVE)

  • Swap STRIPE_SECRET_KEY from sk_test_* to sk_live_*
  • Owner-only $1 self-charge: ring up + Tap to Pay + receipt verified in Stripe Dashboard
  • 3 real customer transactions monitored end-to-end (chargeback & refund flow exercised)

Acceptance gate: $1 owner test + 3 real customer sales clear without manual intervention. No phantom payment_method='Pending' rows older than 30 min in sales.

Phase D · Square cancellation

  • Cancel Square subscriptions ($383/mo savings)
  • Square Reader retired or repurposed as Stripe Terminal device
  • 30-day grace: Square Dashboard kept open for historical lookups only

Acceptance gate: 7 days of clean skateOS-only operation with zero cashier escalations.

Phase E · Brivo door integration

  • Nick provides OAuth client_id + secret (received API key 2026-06-18; OAuth pending)
  • Per-tenant credentials stored via Settings UI (no env-var creds for new parks)
  • Walk-to-door test → Activity Log shows access_granted within 5s

Acceptance gate: 10 consecutive door taps, each correlated 1:1 to a checkin row within 15s.

Phase F · White-label / second park

  • Per-tenant Brivo provisioning Phase 2 (drift-check + signups)
  • Onboarding wizard at Settings → Setup Status reaches 100% for new tenant in < 30 min
  • Sales kit at skateos.com/sales
